# 丝之歌纹章强化：大型 Mod 架构包

本仓库是依据《丝之歌纹章强化.docx》生成的**开发架构与 Agent 交接包**。它不是成品 Mod，而是一个能让本地 Agent、程序员和测试者并行工作的稳定骨架：功能需求有唯一来源，游戏版本相关代码被隔离，复杂机制有可复用的纯逻辑实现，UI 与具体游戏动作绑定留给本地运行环境完成。

## 首先阅读

1. `docs/01_开发计划.md`：按阶段指挥 Agent 开发，包含每阶段输入、产出、验收与回滚标准。
2. `docs/02_代码参考.md`：游戏代码、BepInEx/Harmony API、前置 Mod、参考项目和许可证边界。
3. `docs/03_功能整合.md`：唯一功能需求源。以后改需求，先改这里，再同步 `spec/feature_catalog.json`。
4. `docs/04_实操辅助.md`：本人需要在本地完成的反编译、FSM/贴图检查、运行测试与资料投喂方法。
5. `docs/05_高难代码示例.md`：状态机、伤害管线、丝线护盾、虚拟工具、输入组合键、动态补丁等示例。

## 架构原则

- **规则与游戏绑定分离**：`Core` 只处理数值和状态，`GameInterop` 才接触游戏类、FSM、Unity 对象与前置 Mod。
- **事件驱动而非到处打补丁**：Harmony 补丁只采集事件或提交最终修改，纹章模块订阅统一事件。
- **单一伤害/治疗/资源管线**：暴击、燃爆、毒火、吸血、溢出血、丝线护盾统一排序，避免乘区和重复触发失控。
- **版本可诊断**：游戏方法名、FSM 名、状态名、变量名放在 `config/game-bindings.json`；补丁失败时输出探针报告，而不是静默失效。
- **可回滚**：每个纹章、每类护符增强、每种高风险补丁都能独立开关。

## 目录概览

```text
.
├─ docs/                         五个核心交付文件
├─ spec/                         原文段落与机器可读功能目录
├─ config/                       游戏绑定、平衡参数、功能开关
├─ src/SilkCrestOverhaul/
│  ├─ Core/                      纯逻辑：状态、管线、计时器、资源账本
│  ├─ Features/Crests/           每个纹章一个模块
│  ├─ GameInterop/               BepInEx/Harmony/Needleforge/FSM/Unity 适配
│  ├─ Patches/                   薄补丁层
│  └─ UI/                        UI 投影接口与占位实现
├─ tests/                        纯逻辑测试样例
└─ tools/                        规格校验和本地探针辅助脚本
```

## 当前可直接使用的部分

- 完整需求归档与版本化修改流程。
- 统一运行时状态模型、事件总线、计时叠层、输入组合键、伤害修饰管线、标记血池和丝线护盾示例。
- 动态 Harmony 目标解析与失败诊断模式。
- 10 个纹章模块的文件与职责骨架。
- Agent 分阶段任务书、人工实操清单、测试矩阵和参考资料清单。

## 有意保留为本地绑定的部分

以下内容必须根据用户本机游戏版本、反编译结果和运行时 FSM 实测后填写，架构不会猜测：

- Hornet 控制器、伤害入口、治疗入口、丝线字段、工具库存、护符槽位的真实类型与成员名。
- PlayMakerFSM 的对象路径、FSM 名、状态名、事件名和变量名。
- 原版技能 prefab、动画、tk2d sprite collection、音效和粒子资源路径。
- Needleforge 当前版本的精确公共 API 签名。

本包在 `config/game-bindings.json` 中为这些信息提供了集中填充位置。

## 建议工作流

先执行开发计划的 Phase 0–2，只完成探针、绑定和最小事件闭环；确认攻击、受伤、治疗、丝线、换纹章、坐椅子六类事件稳定后，再实现单个纹章的垂直切片。不要一开始同时写十个纹章。
