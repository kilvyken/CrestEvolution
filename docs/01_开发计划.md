# 01 开发计划

## 0. 总目标与完成定义

目标是实现一个大型《空洞骑士：丝之歌》纹章强化 Mod。第一阶段覆盖文档中的猎手、收割者、漫游者、野兽、女巫、建筑师、萨满、丝母纹章、诅咒纹章和无用之人，并为后续新护符、大招、角色移植与 Boss 系统留下扩展点。

“完成”必须同时满足：

- 功能以 `docs/03_功能整合.md` 为唯一需求源，每个条目有 Feature ID、实现状态和测试用例。
- 游戏版本相关成员全部通过 `GameInterop` 或 `config/game-bindings.json` 访问，核心规则不得直接反射游戏类型。
- 任何高风险功能可在配置中单独关闭；补丁目标失配时不阻止游戏启动。
- 保存/读档、换纹章、坐椅子、死亡、退主菜单、切换场景后状态无泄漏。
- 关键数值逻辑有纯逻辑测试；游戏内功能有手工复现步骤和日志证据。

## 1. Agent 总指令

给本地 Agent 的固定前置提示：

> 先读取 README、五个 docs 文件、`spec/feature_catalog.json` 和当前 `config/game-bindings.json`。不得自行发明游戏类型名、FSM 状态名或资源路径。遇到未知绑定时，在 `artifacts/probes/` 生成所需探针清单并停止该绑定部分，但继续完成与游戏无关的纯逻辑代码。每次提交只实现一个 Feature ID 集合，并更新功能状态、测试和变更日志。

每次 Agent 任务必须包含：

- 输入：Feature ID、已有探针结果、允许修改的目录。
- 输出：代码、测试、绑定变更、运行步骤、已知风险。
- 禁止：复制未知许可证项目代码；把反射散落在纹章模块；用无限 `Update()` 扫描对象；无日志吞异常。

## 2. 分阶段路线

### Phase 0：环境冻结与证据采集

**目标**：确定本机游戏构建、BepInEx、前置 Mod 和程序集实际版本。

任务：

1. 备份存档与游戏目录，建立独立测试存档。
2. 记录游戏版本、平台、Mono/IL2CPP、Unity 版本、BepInEx 版本。
3. 导出 `BepInEx/LogOutput.log`、`*_Data/Managed` 程序集列表、已装插件列表。
4. 安装或准备 CUEP/UnityExplorer 类工具，验证能查看 `HeroController` 候选对象、PlayMakerFSM、SpriteRenderer、tk2d 组件。
5. 把结果写入 `artifacts/environment-report.md`。

验收：游戏可无 Mod 启动；仅装框架和探针插件可启动；日志中没有红色加载错误。

### Phase 1：工程可加载与动态绑定探针

**目标**：插件加载、配置、日志、Harmony 初始化和失败降级可用。

任务：

- 完成 `Plugin.cs`、`ModBootstrap.cs`、配置加载、结构化日志。
- 实现 `DynamicPatchResolver`：按候选类型/方法/签名解析目标。
- 生成 `binding-report.json`：找到、未找到、多匹配、签名不一致。
- 只补丁一个低风险生命周期方法，验证 Patch/Unpatch。

验收：目标找不到时游戏仍可运行；日志明确指出缺失项和候选项。

### Phase 2：六类基础事件闭环

**目标**：建立所有纹章共用的事件层。

必须捕获：

- 攻击开始/命中/伤害结算；
- 玩家受伤前/后；
- 治疗请求/治疗结算；
- 丝线获得/消耗；
- 当前纹章变化；
- 敌人死亡、坐椅子、玩家死亡、场景变化。

产出：`GameEventHub`、`IGameApi`、最小 Harmony 补丁、事件追踪 UI/日志。

验收：每类事件均能在一场普通战斗中输出一次且不重复；暂停或菜单中不误触发。

### Phase 3：纯逻辑核心

**目标**：先在不启动游戏的情况下证明复杂规则可计算。

实现：

- `TimedStackCounter`：独立/共享计时、刷新、清零、阈值事件。
- `CrestRuntimeState`：普通、强化、亡怒、超级亡怒和专属状态。
- `DamagePipeline`：基础伤害、攻击类型、倍率、固定加伤、暴击、追加伤害、最终钳制。
- `ResourceLedger`：丝线、碎片、念珠、虚拟库存和事务回滚。
- `InvulnerabilityLeaseService`：可重入、带来源、自动超时。
- `MarkedHealthPool`：红/绿/紫/蓝血与碎面甲恢复次数转换。
- `InputChordRouter`：上/下 + 治疗、蓄力 + 治疗、二段蓄力 + 下。

验收：核心测试通过；同一攻击不会重复暴击或递归触发燃爆。

### Phase 4：首个垂直切片——猎手

**目标**：以猎手验证从事件、规则、UI 到游戏动作的完整链路。

建议顺序：

1. 连击层数、10 秒持续、受伤不打断。
2. 6/12 层阈值和护符等级投影。
3. 6 层冲刺攻击距离、穿透、无敌租约。
4. 亡怒和超级亡怒。
5. 专属输入映射与虚拟工具消耗。
6. UI：层数、剩余时间、平 A 伤害。
7. 专属护符增强和蓄力剑气。

验收：换纹章、坐椅子、死亡和读档后的状态均符合需求；配置关闭猎手模块后无残留补丁效果。

### Phase 5：共享系统扩展

在写其他纹章前，补齐可复用能力：

- 暴击与保底暴击；
- 周期性强化攻击；
- 火刀/毒刀/蜜酿 Buff 标签系统；
- 追加燃爆、毒火、剑气和多段命中来源标记；
- 攻击距离/速度/眩晕/击退修饰器；
- 工具自动索敌与虚拟库存；
- 护符专属增强注册表；
- UI 投影模型，不直接从 UI 读写玩法状态。

### Phase 6：收割者、漫游者、萨满

这三者优先，因为它们集中验证攻击、技能、暴击、燃爆和多段命中：

- 收割者：强化丝线上限、火刀被动、精准强化攻击、十字斩回丝。
- 漫游者：6 刀进入强化、伤害间隔退出、拼刀必暴、十字绣技能替换。
- 萨满：技能触发灵火、六技能模式、技能减耗、蓄力增强表。

验收：多段攻击计数、丝线回复和暴击只按需求发生；追加伤害不再次触发自身。

### Phase 7：野兽、女巫的生命资源系统

先完成统一 `HealthConversionService`，再分别实现：

- 野兽红血、溢出治疗、红血状态、碎面甲次数转换。
- 女巫绿血、吸血二次触发、绿血状态、无限蓝血上限 99。

验收：普通血、蓝血、标记血、碎面甲、治疗量之间无负数、无超上限、无读档污染。

### Phase 8：建筑师与工具子系统

实现：

- 工具修复、自动补给、齿轮蜂上限、工具伤害倍率。
- 工具形态转换和念珠弹夹事务。
- 各工具蓄力行为、精准时刻倍率、连续饮用与紫血行为。

高风险点：不能直接修改全局工具数据造成其他纹章永久变化；所有改动必须为“当前上下文修饰”。

### Phase 9：丝母纹章

丝母是系统集成验收：

- 1–12 强化阶段；
- 丝线无上限到 99、最低门槛 9；
- 丝线代替生命承伤；
- 混合其他纹章攻击动作；
- 护符叠加 20%–240%；
- 亡怒降阶段、超级亡怒双阶段增长；
- 临时坐椅子/回椅子功能。

验收：所有复合效果均通过共享系统完成，不复制其他纹章模块内部代码。

### Phase 10：诅咒纹章、无用之人与兼容性

- 诅咒纹章：移动/跳跃/攻击强化、飞针减耗、治疗无敌或时间减速模式。
- 无用之人：80% 骰子无敌和暴击。
- 与常见 UI、工具、纹章、新槽位 Mod 进行兼容测试。

### Phase 11：UI、资源与本地化

- UI 只订阅 `UiProjection`；不在 UI 脚本中改变玩法状态。
- 使用原版动作/贴图时记录来源对象、场景、组件、动画 clip 和许可范围。
- 资源缺失时显示占位 UI，不导致玩法失效。
- 中文为主，预留 I18N key。

### Phase 12：发布工程化

- 配置迁移、存档版本号、错误报告打包。
- Thunderstore 元数据、依赖版本下限、第三方许可证说明。
- 性能测试：战斗 10 分钟、对象池、GC 分配、场景切换。
- 回归矩阵覆盖所有纹章 × 亡怒 × 超级亡怒 × 专属状态。

## 3. 每个功能的 Definition of Done

每个 Feature ID 完成时必须有：

1. `03_功能整合.md` 状态从 `待实现` 改为 `已实现/部分实现`。
2. 对应代码位置与配置键。
3. 至少一个纯逻辑测试；若必须依赖游戏，则提供手工测试步骤。
4. 日志中能确认进入、退出、消耗和结算。
5. 换纹章、死亡、坐椅子、读档的重置策略。
6. 与其他伤害来源的递归/叠加规则。

## 4. 推荐提交粒度

- 一次提交只处理一个共享系统或一个纹章的 3–8 个相近 Feature ID。
- 禁止“十个纹章全部初步实现”的大提交。
- 绑定信息与玩法代码分开提交，便于游戏更新后回滚。
- 每次提交包含 `CHANGELOG.md` 和 `artifacts/test-report-*.md`。

## 5. 优先级与风险

| 级别 | 项目 | 原因 |
|---|---|---|
| P0 | 动态绑定、事件闭环、状态重置 | 失败会让所有功能不稳定 |
| P0 | 伤害/治疗/丝线统一管线 | 防止重复触发、数值爆炸和存档损坏 |
| P1 | 猎手垂直切片 | 验证完整架构 |
| P1 | 野兽/女巫生命转换 | 最容易出现不可逆血量错误 |
| P1 | 丝母复合状态 | 依赖最多共享系统 |
| P2 | 专属工具/技能动画与 UI | 可在玩法正确后补充 |
| P3 | 后续角色移植与 AI Boss | 属于下一大版本，不与 1.0 混做 |
