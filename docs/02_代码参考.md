# 02 代码参考

> 核对日期：2026-08-01。外部项目和包会更新，实际开发前需重新确认版本、API 与许可证。本文件说明“参考什么、为什么参考、应放在哪一层”，不代表可直接复制第三方代码。

## 1. BepInEx 与 Harmony

### BepInEx

建议使用能力：

- `BepInPlugin`：声明插件 GUID、名称、版本。
- `BepInDependency`：声明硬依赖或软依赖。
- `BaseUnityPlugin`：生命周期、协程和 Unity API 入口。
- `Config.Bind<T>`：总开关、调试开关、各纹章开关、平衡参数和兼容模式。
- `ManualLogSource` / `Logger`：结构化日志、绑定失败和状态迁移诊断。
- `Paths.ConfigPath`、`Paths.PluginPath`：配置和资源目录。

官方来源：

- https://github.com/BepInEx/BepInEx
- https://docs.bepinex.dev/articles/dev_guide/plugin_tutorial/2_plugin_start.html
- https://docs.bepinex.dev/v5.4.11/articles/dev_guide/plugin_tutorial/4_logging.html
- https://docs.bepinex.dev/master/articles/dev_guide/plugin_tutorial/4_configuration.html

注意：BepInEx 5 与 6 的配置和插件模板存在差异。不要只看网上片段；以本机已加载版本的程序集和示例为准。

### Harmony / HarmonyX

建议优先级：Postfix > Prefix > 事件/原生回调 > Transpiler。

- Prefix：修改参数、短路原方法、建立 `__state`。
- Postfix：读取最终结果、发布事件、做兼容性较好的附加处理。
- Finalizer：记录异常并保证临时状态释放；不要吞掉未知游戏异常。
- Transpiler：仅在没有稳定入口时使用，必须验证 IL 指纹并提供失败降级。
- `AccessTools`：集中解析反射成员；不要在每帧调用。

官方来源：

- https://github.com/pardeike/Harmony
- https://harmony.pardeike.net/articles/patching.html
- https://harmony.pardeike.net/articles/patching-prefix.html
- https://harmony.pardeike.net/api/HarmonyLib.html

## 2. 推荐前置与开发工具 Mod

### Needleforge

用途：新增纹章与工具、创建 `CrestData`、在 BindFSM 注入逻辑、定制 HP 背景和动作集。当前公开说明还包括普通斩、蓄力斩、冲刺攻击、下劈等自定义 moveset；红色工具支持可能随版本变化。

来源：

- Thunderstore: https://new.thunderstore.io/c/hollow-knight-silksong/p/Voidlings/Needleforge/
- NuGet: https://www.nuget.org/packages/Needleforge

本架构中的使用方式：只在 `GameInterop/NeedleforgeAdapter.cs` 引用。`Core` 和各纹章规则不得直接依赖 Needleforge 类型。对原版纹章进行“强化”时，优先修饰当前上下文；只有新增纹章/槽位/工具才调用 Needleforge 注册 API。

截至核对日，NuGet 页面显示 0.9.0 为已发布版本之一，目标为 .NET Standard 2.1，并依赖 BepInEx、HarmonyX、Silksong.FsmUtil、Silksong.PrepatcherPlugin 和 UnityEngine.Modules。版本号不要硬编码为永远正确。

### Silksong.FsmUtil

用途：简化 PlayMakerFSM 的查找与编辑，适合技能动作复用、状态插入、事件转移和变量读取。

来源：

- https://www.nuget.org/packages/Silksong.FsmUtil

使用边界：FSM 修改必须集中在 `GameInterop/FsmAdapter`；先通过 CUEP 导出真实 FSM 图，再写补丁。状态名改变时要能在绑定报告中定位。

### Silksong.Prepatcher

用途：通用预补丁；其插件 API 可监听或修改 PlayerData 变量的 Get/Set，而不必永久改变底层存档值。适合临时槽位、临时上限或“游戏看到的值”投影。

来源：

- https://github.com/silksong-modding/Silksong.Prepatcher
- https://www.nuget.org/packages/Silksong.PrepatcherPlugin

使用边界：不要用它把临时战斗状态写进永久 PlayerData。所有订阅在插件卸载或禁用时解除。

### Silksong.UnityHelper

用途：常用 Unity/游戏对象辅助。是否成为硬依赖取决于本地 Agent 对 API 的实际验证。

来源：

- https://www.nuget.org/packages/Silksong.UnityHelper

### SilkenImpact

用途：参考敌人血条、延迟血条、伤害数字、暴击/火/毒的颜色与对象池设计。其 README 说明它维护敌人当前/最大生命显示，并建议改变最大血量时同步 `HealthManager.initHp`；这对 Boss 或强化怪物兼容尤其有价值。

来源：

- https://github.com/KokomiSensei/SilkenImpact

使用方式：优先做软兼容，检测其插件是否存在；本 Mod 的伤害事件可暴露标签给它，但不应直接控制其内部 UI。复制代码前必须查看仓库许可证；没有明确许可时仅参考架构和公开行为。

### CUEP / UEP For_CUE

用途：运行时检查 Collider、Enemy、Renderer、Material、Sprite/tk2d sprite，导出贴图，并提供 PlayMaker FSM Viewer 和转移记录。这正好补足本地 Agent 无 MCP 时的观察能力。

来源：

- https://github.com/MCXGK3/UEP/tree/For_CUE

使用方式：开发工具，不作为发布硬依赖。把导出的 FSM、对象路径、组件列表和截图放进 `artifacts/probes/` 投喂给 Agent。

## 5. 应优先调用的游戏原生能力

本地反编译后要建立 `game-bindings.json`，至少覆盖以下概念。表中名称是“概念名”，不是保证存在的真实类型名。

| 概念 | 需要定位的原生入口 | 用途 |
|---|---|---|
| 玩家攻击 | 攻击状态开始、Hitbox 生成、命中结算 | 计连击、改距离、穿透、剑气、精准蓄力 |
| 伤害接收 | 玩家受伤前后、无敌判断 | 受伤不打断、丝线护盾、骰子无敌 |
| 敌人生命 | 敌人受伤、死亡 | 暴击、燃爆、击杀延时、回丝/碎片 |
| 治疗/Bind | 治疗请求、消耗、完成、中断 | 专属状态、二次吸血、红绿血转换 |
| 丝线资源 | 获得、消费、上限查询 | 双倍槽、99 上限、减耗、虚拟工具 |
| 当前纹章 | 装备、切换、CrestData/BindFSM | 激活模块、槽位与动作变化 |
| 工具 | 使用、库存、修复、补给、投射物生成 | 无库存使用、自动补给、自动索敌 |
| 护符/工具槽位 | 装备查询、槽位颜色、等级 | 专属护符、升级槽、超级记忆盒 |
| 坐椅子/存档 | Bench、Respawn、Save | 重置层数、传送、持久状态 |
| UI | 血条、丝线条、护符图标、世界空间数字 | 层数、计时圆环、标记血、国王之心 |
| PlayMaker FSM | 技能/动作 FSM、状态、事件、变量 | 复用原版动作和贴图 |

## 6. Unity API 使用建议

- `GameObject` / `Component` / `Transform`：只缓存已验证引用，场景切换后重新绑定。
- `Animator`、tk2d 组件或 PlayMakerFSM：优先复用原版动作，不复制游戏资源到发布包。
- `Object.Instantiate`：剑气、灵火、UI 等需配对象池，避免每次攻击分配。
- `Physics2D` / Collider2D：自动索敌和范围技能必须使用 LayerMask，禁止全场 `FindObjectsOfType` 每帧扫描。
- `Time.unscaledTime` 与 `Time.time`：暂停、时间减速和 UI 倒计时要明确使用哪一个。
- `SceneManager.sceneLoaded`：重新绑定场景对象和清理失效引用。
