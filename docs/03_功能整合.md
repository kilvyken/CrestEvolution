# 03 功能整合（唯一需求源）

## 0. 修改规则

本文件是玩法需求的唯一人工可读来源。修改任何功能时：

1. 保留或新增 Feature ID；不要复用已删除 ID。
2. 写清触发条件、持续时间、资源消耗、叠加规则、退出/重置条件、UI 和异常情况。
3. 同步 `spec/feature_catalog.json` 或在 Agent 任务中明确由脚本同步。
4. 实现状态使用：`待实现`、`开发中`、`部分实现`、`已实现`、`已取消`。
5. 原文未给出精确值的地方标为 `待实测/待定`，不得由 Agent 静默猜测。

## 1. 全局术语与统一规则

- **强化状态**：各纹章自己的强化模式；必须有明确进入、刷新、退出和重置策略。
- **亡怒**：一格面具时自动进入，除非条目另有说明。
- **超级亡怒**：亡怒的进阶状态。部分纹章自动进入，部分需要组合键和资源条件。
- **专属状态**：通常由 `下 + 治疗` 或 `上 + 治疗` 切换，输入必须经 `InputChordRouter` 仲裁。
- **专属技能**：通常为 `攻击蓄力 + 治疗键`；后续大招可能使用二段蓄力与方向键。
- **专属护符增强**：原版护符在指定纹章下改变效果；离开纹章后必须恢复原版行为。
- **护符升级槽**：计划设立两个特殊槽位，仅特定纹章拥有；与专属护符相关但不是同一系统。
- **追加伤害来源标签**：剑气、燃爆、毒、火、灵火、工具、多段攻击必须带 `SourceTag`，默认不能递归触发自身。
- **状态重置默认值**：换纹章清理临时战斗状态；坐椅子清理明确写“坐椅子重置”的状态；死亡清理所有非持久战斗状态。超级亡怒条目明确“切换纹章不退出”的除外。
