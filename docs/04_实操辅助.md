# 04 实操辅助

本文件专门解决“本地 Agent 没有游戏运行、资源浏览或 MCP 能力”的问题。本人负责观察和导出，Agent 负责根据证据写代码。不要让 Agent 猜游戏内部名称。

## 1. 本人需要准备的工具

### 必需

- BepInEx 对应本机游戏架构的版本。
- CUEP/UEP For_CUE 或可用的 UnityExplorer：查看对象、组件、Collider、Renderer、Material、PlayMakerFSM、tk2d sprite，并导出贴图。
- ILSpy 或 dnSpyEx：只用于查看本机程序集类型、方法、字段和调用关系。
- 文本编辑器与 Git。
- 独立测试存档和存档备份脚本。

### 推荐

- AssetRipper / AssetStudio / UABEA：仅用于本地分析 Unity 资源。发布包不要重新分发原版资源。
- RenderDoc：粒子、Shader 或渲染顺序难以理解时使用。
- Process Monitor：确认插件加载路径和配置读写。
- 屏幕录制工具：记录输入、帧时序和错误复现。

## 3. 如何给 Agent 提供反编译资料

每个需要绑定的功能建立一个小包，不要丢整套游戏 DLL：

```text
artifacts/probes/attack/
├─ request.md                 想找什么入口
├─ types.txt                  候选类型完整名
├─ methods.txt                方法签名与反编译片段
├─ call-chain.md              谁调用谁
├─ runtime-log.txt            实际触发日志
└─ screenshots/               运行时对象/FSM 截图
```

### 反编译片段最少包含

- 类型完整名、程序集名。
- 方法完整签名和访问级别。
- 与需求相关的 30–80 行上下文。
- 字段和属性类型。
- 上游调用者和下游被调用者。
- 是否为协程、FSM Action、Unity 消息或普通方法。

不要只发一张没有类型名的截图。

## 4. PlayMaker FSM 调查流程

以“治疗被攻击中断”为例：

1. 进入可安全治疗的场景。
2. 在 CUEP 中选中玩家对象，列出所有 PlayMakerFSM。
3. 逐个查看名字中可能含 Bind、Heal、Silk、Hero 的 FSM。
4. 开启 FSM Viewer 的 Recording。
5. 依次执行：正常治疗、丝线不足治疗、治疗中受伤、空中尝试治疗。
6. 导出每次的状态序列、事件、变量变化和对象路径。
7. 把对应动作组件的类型和字段一起记录。

推荐记录表：

| 场景 | 对象路径 | FSM 名 | 起始状态 | 输入事件 | 中间状态 | 完成/中断状态 | 关键变量 |
|---|---|---|---|---|---|---|---|

FSM 补丁原则：

- 先插入旁路状态或事件，不直接重写整张 FSM。
- 对状态名使用候选列表和状态动作指纹双重匹配。
- 修改前克隆/记录原始 Action 列表，禁用功能时恢复。

## 5. 贴图、动画与原版动作调用

文档要求大部分专属技能复用游戏已有动作和贴图。本人需要为每个资源建立 `asset-manifest.csv`：

```csv
feature_id,scene,game_object_path,component_type,asset_name,animation_clip,sprite_collection,material,notes
HUN-050,...
```

### 导出/观察步骤

1. 找到使用目标动作的原版敌人或 Boss。
2. 记录场景、对象层级路径、Prefab/实例名。
3. 记录 Animator/tk2d/PlayMakerFSM 组件。
4. 导出 sprite 名单或本地 PNG 仅供定位，不提交到公开仓库。
5. 记录命中框生成时间、移动曲线、音效、粒子和销毁方式。
6. Agent 只写“运行时从原版对象克隆/池化”的代码。

### 投喂 Agent 的最小资料

- 一段 5–15 秒视频，带输入显示。
- FSM 状态序列。
- 对象和组件树截图。
- 关键类型/方法反编译片段。
- 目标资源的名称和路径。
- 期望修改：速度、范围、颜色、判定次数、资源消耗。

## 6. 运行测试方法

### 日志级别

- `Info`：插件加载、版本、模块启用、场景切换。
- `Debug`：状态进入/退出、层数变化、资源事务。
- `Trace`：每次攻击/命中；仅测试时开启。
- `Warning`：绑定缺失、兼容模式、数值被钳制。
- `Error`：功能异常并自动禁用该模块。

### 每个功能的测试记录

```text
Feature ID：
游戏版本：
前置版本：
起始存档/场景：
装备与资源：
操作步骤：
预期结果：
实际结果：
日志时间范围：
截图/视频：
是否重现：
是否影响存档：
```

### 必测生命周期

每个纹章至少测试：

1. 新进存档。
2. 原地换纹章。
3. 坐椅子后换纹章。
4. 受伤、死亡、复活。
5. 进出场景。
6. 退主菜单再读档。
7. 关闭对应功能配置后读档。
8. 与 UI Mod、工具 Mod 同时启用。

## 7. 数值与碰撞调试

- 开启命中框/Collider 可视化，记录 Layer、Tag、尺寸、偏移和存活时间。
- 伤害日志必须包含 `attackId`、`sourceTag`、`baseDamage`、每个修饰器和最终值。
- 多段攻击记录 `sequenceId` 与 `hitIndex`，防止一次攻击错误累加多个“第一刀”或保底暴击。
- 自动索敌记录候选数量、距离、角度、遮挡和选中目标。
- 无敌记录租约来源、开始、结束和剩余来源，避免某个协程提前取消其他无敌。

## 8. 性能检查

重点观察：

- `Update()` 中是否有反射、LINQ、字符串拼接、对象搜索。
- 剑气、灵火、伤害数字是否使用对象池。
- 场景切换后事件是否重复订阅。
- UI 是否每帧重建层级或材质实例。
- 10 分钟战斗后的内存和 GC 峰值。

建议日志中每 60 秒输出一次：活动对象池数量、事件订阅数量、当前纹章状态、未释放无敌租约和挂起资源事务。

## 9. 存档安全

- 测试前复制整个存档目录，并保留至少三个时间点。
- 临时血量上限、护符等级、丝线上限优先做“读取投影”或运行时状态，不永久写 PlayerData。
- 需要持久化的只有本 Mod 自己的数据，如超级记忆盒数量、解锁状态和配置版本。
- 保存格式带 `schemaVersion`，迁移失败时备份旧文件并禁用持久功能。
- 严禁在 Harmony Prefix 中写存档后跳过原方法，除非已验证完整事务。

## 10. Agent 无法继续时应返回什么

Agent 不应只说“缺少 API”。它应输出：

1. 需要定位的概念与用途。
2. 建议搜索的类型/方法关键词。
3. 需要执行的游戏内动作。
4. 需要截图或导出的 CUEP 页面。
5. 预期的候选签名格式。
6. 拿到资料后将修改的文件列表。

这样本人可以一次收集完整资料，而不是来回补问。
